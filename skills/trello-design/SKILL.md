# Trello → Дизайн (изучить задачу и сделать концепт)

Автоматический маршрут: прочитать карточку Trello целиком → разобрать ТЗ →
сделать концепт по стандартам качества → отдать результат + бриф для финала
в Claude Design. Не заставляй пользователя расписывать шаги — веди сам.

## Предусловие

Нужны инструменты сервера **trello-deep** (`trello_list_attachments`,
`trello_fetch_attachment`, `trello_get_comments`, `trello_get_card_history`).
Если их нет — скажи пользователю установить плагин (README, install.ps1 /
install.sh) и останови навык.

## Шаг 1. Изучить карточку (обязательно — не выдумывай требования)

1. Описание/метаданные карточки — штатным Trello-коннектором (название, desc,
   список, метки, участники).
2. `trello_get_comments(card, limit=1000)` — прочитать всё обсуждение. Часто
   именно в комментариях лежит настоящий бриф, правки и финальное решение.
3. `trello_list_attachments(card)` — увидеть, что приложено.
4. `trello_fetch_attachment(...)` для брифа, бренд-гайда и референсов. Затем:
   - PDF — прочитать/отрендерить страницы (при отсутствии рендера — извлечь текст);
   - docx — извлечь текст;
   - картинки — **посмотреть глазами** (это ключевая ценность плагина);
   - zip/rar — распаковать и посмотреть содержимое (для больших наборов —
     собрать контактный лист/montage и просмотреть выборку, не молча ограничивая).

Не начинай дизайн, пока не увидел бриф, бренд-материалы и референсы.

## Шаг 2. Собрать структурированное ТЗ

Извлеки и зафиксируй (кратко, по пунктам):

- **Что делаем** (логотип / баннеры / лендинг / айдентика; форматы, размеры).
- **О клиенте и продукте**, рынок, аудитория, тональность.
- **Жёсткие требования** из брифа и комментариев (цитируй важное дословно).
- **Бренд**: цвета (HEX), шрифты, существующие ассеты.
- **Референсы** (бренды/ссылки/приложенные примеры) — на что равняться.
- **Do / Don't** — что обязательно и что запрещено.
- **Деливери**: полный список того, что должно быть на выходе.
- **Финальное решение**, если в комментариях уже что-то утвердили.

Сначала покажи это ТЗ пользователю (2–3 абзаца) — чтобы он видел, что ты понял
задачу правильно.

## Шаг 3. Сделать концепт (здесь) + бриф для Claude Design

Сделай **быстрый визуальный концепт прямо здесь** (борд: знак/лого + варианты +
палитра + типо-заметка, либо HTML-мокап баннера/лендинга) и **отдельный бриф
`.md` для Claude Design**, куда финалить.

Применяй чек-лист качества (fintech / clean), если бренд-гайд не диктует иное:

- **Геометрия и сетка** — выверенные пропорции, единый модуль, оптический баланс.
- **Типографика** — геометрический гротеск (Inter / Geist / TT Commons и т.п.),
  плотный трекинг в вордмарке, чёткая иерархия.
- **Цвет** — ограниченная палитра из бренда; основной + 1 акцент + нейтрали;
  контраст под доступность; без «луже» цветов.
- **Флэт** по умолчанию — без градиентов в основном лого (градиент допустим в
  маркетинговых баннерах, если бренд разрешает).
- **Читаемость в мелком** — знак обязан работать в favicon/app-icon; проверь.
- **Референсы уровня** Stripe / Revolut / Linear / Vercel — clean, memorable,
  timeless, globally scalable.
- **Система, а не одна картинка** — горизонт./вертик. lockup, только знак,
  monochrome, reversed, favicon/app.

Не обещай пиксель-точный продакшн-финал: это **концепт-уровень**. Финал —
в Claude Design или у дизайнера. Так и говори пользователю.

## Шаг 4. Отдать результат

- Покажи концепт (картинку/мокап) и приложи файлы (борд, иконку, бриф `.md`).
- Дай короткую инструкцию, как довести в Claude Design (приложить файлы + вставить бриф).
- Предложи **прикрепить результат обратно в карточку** через
  `trello_upload_attachment` и/или оставить комментарий `trello_add_comment`.

## Guardrails

- **Запись в Trello (комментарий/вложение) — только с явного согласия пользователя.**
  Инструменты необратимы: сначала предпросмотр (confirm=False), затем, после «да»,
  вызов с confirm=True.
- `@упоминания` в комментариях шлют реальные уведомления людям — не добавляй их
  без просьбы.
- Не выдумывай требования, которых нет в карточке. Если чего-то не хватает
  (форматы, палитра) — спроси или явно пометь предположение.
